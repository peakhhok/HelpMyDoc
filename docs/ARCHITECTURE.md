# 구조 (Architecture)

HelpMyDoc은 **"AI가 지금 사용자가 보고 있는 페이지를 안다"** 는 한 가지 아이디어에 집중한 PDF 리더입니다.
새 기능을 얹을 때 이 문서의 확장 지점을 따르면 기존 코드를 크게 건드리지 않아도 됩니다.

## 한눈에 보기

```
┌──────────────────────── 브라우저 (React) ────────────────────────┐
│  PdfViewer ──현재 페이지·선택 텍스트──▶ App 상태                     │
│      │                                      │                        │
│  pdf.ts (페이지 텍스트 추출·캐시)              ▼                        │
│      └──────────────▶ context.ts ──▶ ChatPanel ──▶ Provider.stream() │
└───────────────────────────────────────────────┬──────────────────────┘
                                                │
              ┌─────────────────────────────────┴───────────────┐
              ▼                                                 ▼
     api provider                                 claude-code provider
     (브라우저 → api.anthropic.com)                (브라우저 → 로컬 브리지 → `claude -p`)
```

## 질문 한 번의 흐름

1. `PdfViewer`가 스크롤 위치로 **현재 페이지**를 계산해 `App`에 알린다. (화면 세로 중앙에 걸린 쪽)
2. 사용자가 질문을 보내면 `ChatPanel`이 `context.buildPrompt()`로 `현재 페이지 ±N쪽`의 텍스트 + 선택 텍스트 + 질문을 하나의 프롬프트로 만든다.
3. 선택된 `Provider`의 `stream()`이 AI를 호출하고, 글자가 도착할 때마다 `onText`로 화면을 갱신한다.
4. 답변이 끝나면 `docStore`에 대화를 저장하고, 보던 페이지는 스크롤이 멈춘 뒤 저장한다. PDF를 열 때 파일 내용 해시로 기록을 찾아 대화와 마지막 페이지를 복원한다. (화면과 저장소에는 전체 대화가 남지만 AI에게는 최근 대화만 보낸다 — 메시지 100개 또는 총 6만 자 중 먼저 걸리는 한도)
5. **문서 문맥은 이번 턴에만 붙인다.** 이전 턴은 질문 원문과 답변만 history로 보낸다 → 대화가 길어져도 토큰이 문서 문맥만큼 불어나지 않는다.

## 확장 지점

### 새 AI 연결 방식 추가 (Ollama 등)

1. `src/lib/providers/<name>.ts`에 `Provider`를 구현한다. (`label`, `short`, `group`, `describe`, `unavailableReason`, `stream`)
2. `src/lib/providers/index.ts`의 `PROVIDERS`·`PROVIDER_ORDER`에 등록하고, `src/lib/settings.ts`의 `ProviderId`와 설정 필드를 추가한다.
3. `SettingsDialog`에 해당 방식의 입력란을 추가한다.
4. `providers.test.ts`에 사용 가능 조건 테스트를 추가한다.

`stream()`은 `history`(이전 턴)와 `prompt`(이번 턴 문맥+질문)를 받는다. 서버가 대화를 기억하지 않는 방식이면 `claudeCode.ts`의 `toTranscript`처럼 history를 텍스트로 이어 붙인다.

### AI에게 보여줄 문맥을 늘리기 (스캔본 이미지, 목차, 전체 색인 …)

지금 `buildPrompt()`는 텍스트만 만든다. 이미지·검색 결과 같은 새 문맥은 `context.ts`에서 "문맥 조각"으로 추가하고, Provider가 이를 받을 수 있게 `ProviderRequest`를 확장한다. (예: `prompt: string` → 텍스트와 이미지 파트의 배열)

### 다른 문서 포맷

`PdfViewer` + `pdf.ts`가 "페이지 단위 렌더링 + 페이지 텍스트 + 현재 페이지 콜백"을 제공하는 부분이다. 같은 세 가지를 제공하면 다른 포맷의 뷰어로 바꿀 수 있다. `context.ts`는 이미 `numPages`와 `getPageText(page)`만 요구한다.

## 설계 결정과 이유

- **문서 식별은 파일 이름이 아니라 내용 해시**: 이름이 바뀌어도 같은 문서로 알아보고, 같은 이름의 다른 파일은 섞이지 않는다. (pdf.js fingerprint 는 같은 도구가 같은 시각에 만든 서로 다른 PDF에서 겹칠 수 있어 쓰지 않는다. 해시를 못 쓰는 환경에서만 대체값으로 사용)
- **저장소 사용 불가 시 조용히 건너뜀**: 시크릿 모드 등에서 IndexedDB 를 못 써도 앱은 저장 없이 정상 동작한다.
- **연결 점검은 실행할 때만 막는다**: 설정을 마친 사용자가 Claude Code 방식으로 열었는데 준비가 안 됐으면 시작 화면에서 안내하고, 사용 중에 로그인이 풀리면 화면을 막지 않고 채팅창 배너로만 알린다. 창으로 돌아올 때마다 상태를 조용히 다시 확인해 터미널에서 로그인하고 돌아오면 바로 반영된다. API 키 방식이나 브리지가 없는 환경은 이 점검의 대상이 아니다.
- **설치는 앱이 대신 실행하지 않는다**: 공식 설치 명령을 보여주고 사용자가 직접 실행하게 한다. 인터넷에서 받은 스크립트를 앱이 실행하지 않는다.
- **로그인은 "고정된 명령 하나"만 실행한다**: "로그인 시도하기" 버튼은 브리지의 `POST /api/claude-code/login` 으로 `claude auth login` 만 실행한다(셸 없음, 요청 값은 명령에 쓰지 않음, 표준입력 차단, 연결이 끊기면 종료, 동시에 하나). 브라우저에서 로그인하면 Claude Code 가 직접 마무리하므로 앱은 입력도 로그인 정보도 다루지 않고 이후 `claude auth status` 로 결과만 확인한다. 앱 안 터미널(임의 셸)은 공격 면이 커서 만들지 않았다.
- **사용량은 Claude Code가 알려주는 값만 전달한다**: 브리지는 답변마다 토큰 수와 5시간/7일 한도 사용률·초기화 시각만 화면으로 보내고, 세션 ID와 `total_cost_usd`는 보내지 않는다. 비용 값은 정가로 환산한 숫자라 구독에서는 실제 청구액이 아니어서 혼동을 부르기 때문이다. API 방식은 응답의 `usage`로 토큰 수만 표시한다(요금은 모델별 단가를 알아야 해서 표시하지 않음).
- **연결을 도중에 바꿔도 대화가 이어진다**: 대화는 앱이 들고 있고 매 질문마다 (최근 분량의) 이전 대화를 선택된 연결에 넘기기 때문이다. 연결 전환은 설정 값 하나(`provider`)를 바꾸는 것이다. 대신 이전 대화가 새로 고른 회사에도 전송된다는 점을 README의 프라이버시 항목에 적었다.
- **CLI 어댑터**: 공식 CLI마다 다른 부분(인자, 로그인 확인, 출력 형식)은 어댑터 한 곳에 두고, 브리지는 보안 검사·프로세스 관리·스트리밍만 맡는다. 새 CLI를 더하려면 어댑터를 추가하면 된다.
- **Codex는 실험 기능, 기본 꺼짐**: 약관 허용 여부가 불확실하고 도구를 완전히 끌 수 없어(읽기 전용 샌드박스 + 지침 + `--ephemeral` + 사용자 설정 무시로 제한) 사용자가 위험 안내에 동의한 뒤에만 실행한다. 모델이 도구를 쓰려 하면 답변 아래에 알린다. 윈도우의 npm 래퍼(`codex.cmd`)는 셸 없이 실행할 수 없어 옆의 JS 진입점을 직접 실행한다.
- **Gemini 구독 로그인은 지원하지 않는다**: Google 약관이 서드파티 도구의 접근을 금지하고 불이익이 사용자 계정에 가기 때문이다. API 키 방식만 지원한다.
- **자동 업데이트는 로컬 서버 API 로 화면과 잇는다**: 창에 preload/IPC 를 추가하지 않고(공격 면 최소화) 이미 있는 로컬 서버에 `/api/app/update` 를 두었다. 브라우저 버전에는 이 경로가 없어 배너가 보이지 않는다. 설치 요청(`POST …/install`)은 업데이트가 _준비됨_ 일 때만 받고 Host/Origin 검사를 거친다.
- **업데이트 출처와 신뢰**: GitHub Releases(HTTPS)의 `latest*.yml` 에 적힌 sha512 로 내려받은 파일의 무결성을 확인한다. 코드 서명이 없으므로 서명 검증은 하지 않는다(electron-updater 는 게시자 이름이 없으면 건너뜀). 즉 신뢰의 기준은 이 저장소의 쓰기 권한이다. 현재 배포 대상은 윈도우뿐이다. (코드는 AppImage 리눅스도 켜 두지만 CI 에서 검증하지 않고, 서명이 없는 맥은 켜지 않는다.)
- **서버 없음 (BYOK)**: 문서와 API 키가 개발자 서버를 거치지 않는다. 운영 비용·개인정보 부담이 없고 오픈소스로 배포하기 쉽다.
- **데스크톱은 Electron + 같은 로컬 서버**: 브리지(Node)를 그대로 재사용하고 브라우저 버전과 코드가 하나다. 창에는 `nodeIntegration` 없이 `http://127.0.0.1:<고정 포트>`를 로드한다. 포트를 고정하는 이유는 localStorage(설정)가 포트별로 분리되기 때문이다. (크기가 크고 로컬 포트가 열린다는 단점이 있어, 필요해지면 IPC 방식이나 Tauri로 옮길 수 있다.)
- **보이는 쪽만 렌더링**: 500쪽 문서도 DOM·메모리가 일정하다. 현재 페이지는 이분 탐색으로 계산해 스크롤 중에도 가볍다.
- **현재 페이지 ±N쪽만 전송**: 비용과 정확도의 균형. 범위는 설정에서 바꿀 수 있다.
- **Claude Code 연결은 로컬 브리지로**: 브라우저는 프로세스를 실행할 수 없다. 구독 로그인은 Claude Code가 직접 처리하고, 앱은 토큰을 보지 않는다. (아래 제약 참고)
- **브리지는 순수 채팅으로만 실행**: 내장 도구 비활성화(`--tools ""`), MCP·슬래시 명령·프로젝트 설정 비활성화, 세션 저장 안 함, 빈 임시 폴더에서 실행.

## 지켜야 할 제약

Anthropic 약관([Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance), [Usage Policy](https://www.anthropic.com/legal/aup))상 아래를 어기는 변경은 받지 않는다.

1. 구독 로그인 토큰·세션을 **읽거나 저장하거나 중계하지 않는다.**
2. Claude Code 바이너리를 **수정하거나, 인증 방식을 끄거나, 다른 클라이언트인 척하지 않는다.**
3. 브리지는 **`127.0.0.1`에서만** 열고 Host/Origin 검사를 유지한다. 서버로 호스팅해 여러 사람이 쓰게 하는 구성은 만들지 않는다.
